# الف کپیتال — وب‌سایت

سایت ایستای الف کپیتال. ۱۸ صفحه فارسی/RTL که از یک ژنراتور پایتون ساخته می‌شوند.

```bash
make serve     # پیش‌نمایش روی http://localhost:8000
make check     # ساخت + بررسی لینک، رندر، سرریز و منوها
make deploy    # انتشار روی سرور
```

---

## ⚠️ اولین چیزی که باید بدانید

**پوشه `dist/` خروجی است، نه منبع.** با هر `make build` کاملاً پاک و بازساخته می‌شود.
هرگز فایل‌های داخل `dist/` را ویرایش نکنید — تغییرتان از بین می‌رود.
همیشه فایل منبع را عوض کنید و دوباره build بگیرید.

---

## کجا چه چیزی را عوض کنم؟

| می‌خواهم … | فایل |
|---|---|
| اسم، تلفن، ایمیل، نشانی، شماره ثبت | `site/config.py` → `BRAND` |
| **قیمت پلن‌ها** | `site/config.py` → `PRICING` |
| **آیتم‌های منوی بالا** (اضافه/حذف/جابه‌جایی) | `site/config.py` → `NAV` |
| دکمه‌های کنار منو | `site/config.py` → `NAV_CTA` |
| ستون‌های فوتر | `site/config.py` → `FOOTER` |
| نوار پایین موبایل | `site/config.py` → `BOTTOM_NAV` |
| اقلام نوار قیمت متحرک | `site/config.py` → `TICKER` |
| **رنگ‌ها، فونت، فاصله‌ها، سایه‌ها** | `site/theme.css` → بلوک `:root` بالای فایل |
| ظاهر یک کامپوننت (دکمه، کارت، جدول…) | `site/theme.css` |
| **متن یک صفحه** | `site/pages/<نام صفحه>.py` |
| ساختار `<head>`، نوار بالا، فوتر | `site/layout.py` |
| اضافه کردن صفحه جدید | ۳ قدم پایین ↓ |

بعد از هر تغییر: `make check`

### رنگ‌ها

همه رنگ‌ها توکن CSS هستند و در `:root` بالای `theme.css` تعریف شده‌اند.
برای عوض کردن کل هویت رنگی، فقط همان بلوک را عوض کنید — نه تک‌تک کامپوننت‌ها را.
مستند کامل پالت با اعداد کنتراست: `docs/palette.html`

## اضافه کردن صفحه جدید

```python
# ۱) site/pages/blog.py
HTML = """<section class="sec"><div class="wrap">
  <h1>وبلاگ</h1>
</div></section>"""
JS = ""
```

```python
# ۲) site/config.py → PAGES
"blog": "blog.html",
```

```python
# ۳) site/build.py → import و یک ردیف در SITE
import blog
("blog", "وبلاگ | الف کپیتال", "توضیح متا", blog.HTML, blog.JS),
```

نوار بالا، فوتر، فونت، تم و اسکریپت‌های مشترک خودکار اضافه می‌شوند.
اگر می‌خواهید در منو هم بیاید، یک خط به `config.NAV` اضافه کنید.

## ساختار

```
site/
  config.py     ← تنظیماتی که زیاد عوض می‌شوند (برند، قیمت، منو)
  theme.css     ← تنها فایل استایل پروژه
  layout.py     ← قالب مشترک: head، نوار بالا، فوتر، JS مشترک
  build.py      ← نقطه ورود ساخت
  pages/        ← محتوای هر صفحه، یک فایل برای هر صفحه
  static/       ← فایل‌های ثابت (فونت، تصویر) → کپی می‌شود در dist/
tests/check.py  ← بررسی خودکار
deploy/         ← Caddy + docker-compose + اسکریپت انتشار
docs/           ← سند طراحی و مستند پالت
dist/           ← خروجی (در git نیست)
```

**چرا ژنراتور و نه ۱۸ فایل HTML؟**
نوار بالا و فوتر در همه صفحات یکسان‌اند. با HTML دستی، هر تغییر منو یعنی ۱۸ ویرایش
و اینکه یکی‌شان جا بماند. اینجا یک جا عوض می‌کنید و `make build` بقیه را می‌سازد.

## تست خودکار

`make check` این‌ها را می‌سنجد:

1. لینک‌های داخلی و لنگرها (`#id`) — چه در همان صفحه، چه بین صفحات
2. خطای JavaScript در هر صفحه
3. سرریز افقی در ۴ عرض: ۱۴۴۰ / ۱۲۸۰ / ۷۶۸ / ۳۹۰
4. منوهای نوار بالا — **بصری**: بسته باید پنهان باشد، باز باید واقعاً دیده شود، ابعاد درست داشته باشد و از لبه صفحه بیرون نزند
5. نشکستن ارتفاع نوار بالا

بند ۴ عمداً وضعیت بصری را می‌سنجد نه کلاس‌های CSS را. یک بار استایل منو به یکی از
صفحات نرسید و چون تست فقط کلاس‌ها را چک می‌کرد، لو نرفت.

نصب پیش‌نیاز تست (اختیاری — build بدون آن هم کار می‌کند):

```bash
pip install -r requirements.txt && playwright install chromium
```

## فونت

در حالت پیش‌فرض Vazirmatn از Google Fonts می‌آید که برای توسعه محلی خوب است،
اما **برای کاربر ایرانی کند یا مسدود است**. پیش از انتشار:

```bash
make fonts                                    # دانلود فونت
# سپس در site/config.py:  SELF_HOSTED_FONT = True
make build
```
