# Alef Capital — Website

The static Alef Capital site. 18 Persian/RTL pages generated by a Python generator.

```bash
make serve     # preview at http://localhost:8000
make check     # build + check links, rendering, overflow and menus
make deploy    # publish to the server
```

---

## ⚠️ First thing you need to know

**The `dist/` folder is output, not source.** Every `make build` wipes and rebuilds it completely.
Never edit files inside `dist/` — your change will be lost.
Always change the source file and build again.

---

## Where do I change what?

| I want to … | File |
|---|---|
| Name, phone, email, address, registration number | `site/config.py` → `BRAND` |
| **Plan pricing** | `site/config.py` → `PRICING` |
| **Top menu items** (add/remove/reorder) | `site/config.py` → `NAV` |
| Buttons next to the menu | `site/config.py` → `NAV_CTA` |
| Footer columns | `site/config.py` → `FOOTER` |
| Mobile bottom bar | `site/config.py` → `BOTTOM_NAV` |
| Items in the scrolling price ticker | `site/config.py` → `TICKER` |
| **Lock the dashboards behind sign-up again** | `site/config.py` → `PAYWALL` |
| **Colors, fonts, spacing, shadows** | `site/theme.css` → the `:root` block at the top of the file |
| A component's look (button, card, table…) | `site/theme.css` |
| **The text of a page** | `site/pages/<page name>.py` |
| `<head>` structure, top bar, footer | `site/layout.py` |
| Adding a new page | 3 steps below ↓ |

After every change: `make check`

### Colors

All colors are CSS tokens, defined in `:root` at the top of `theme.css`.
To change the whole color identity, change only that block — not each component.
Full palette documentation with contrast numbers: `docs/palette.html`

## Adding a new page

```python
# 1) site/pages/blog.py
HTML = """<section class="sec"><div class="wrap">
  <h1>وبلاگ</h1>
</div></section>"""
JS = ""
```

```python
# 2) site/config.py → PAGES
"blog": "blog.html",
```

```python
# 3) site/build.py → import and one row in SITE
import blog
("blog", "وبلاگ | الف کپیتال", "meta description", blog.HTML, blog.JS),
```

The top bar, footer, font, theme and shared scripts are added automatically.
If you also want it in the menu, add one line to `config.NAV`.

## Structure

```
site/
  config.py     ← settings that change often (brand, pricing, menu)
  theme.css     ← the project's only stylesheet
  layout.py     ← shared template: head, top bar, footer, shared JS
  build.py      ← build entry point
  pages/        ← per-page content, one file per page
  static/       ← static files (fonts, images) → copied into dist/
tests/check.py  ← automated checks
deploy/         ← Caddy + docker-compose + deploy script
docs/           ← design document and palette documentation
dist/           ← output (not in git)
```

**Why a generator and not 18 HTML files?**
The top bar and footer are identical on every page. With hand-written HTML, every menu change means 18 edits
and one of them getting missed. Here you change it in one place and `make build` produces the rest.

## Automated tests

`make check` measures the following:

1. Internal links and anchors (`#id`) — both within a page and across pages
2. JavaScript errors on each page
3. Horizontal overflow at 4 widths: 1440 / 1280 / 768 / 390
4. Top-bar menus — **visually**: closed must be hidden, open must actually be visible, have the right dimensions, and not run off the edge of the screen
5. The top bar's height not breaking

Item 4 deliberately measures visual state rather than CSS classes. Once the menu styles failed to reach one of
the pages, and because the test only checked classes, it went undetected.

Installing the test prerequisites (optional — the build works without them):

```bash
pip install -r requirements.txt && playwright install chromium
```

## Light and dark

Both themes ship. The top bar has a toggle; the choice is stored in
`localStorage`, and with nothing stored the visitor's OS preference decides. A
small script in `<head>` applies the theme before the first paint, so a
dark-theme visitor never gets a white flash.

Dark is **selected, not inverted**: `:root[data-theme="dark"]` in `theme.css`
redefines the same tokens with values chosen against the dark surface. No
component is restyled — that is the point of keeping every colour in one block.
If you add a component, use the tokens (`var(--surface)`, `var(--ink-800)`,
`var(--border)`) and it works in both themes for free. A literal `#fff` will
not.

## Fonts

By default Vazirmatn comes from Google Fonts, which is fine for local development,
but **for Iranian users it is slow or blocked**. Before publishing:

```bash
make fonts
make build
```

That is the whole procedure — there is no setting to flip. If the woff2 files are
present under `site/static/assets/fonts/`, the build self-hosts the font; if they
are not, it falls back to Google Fonts. Those files are gitignored, so the server
self-hosts and your laptop does not, from the same commit.

To force it either way (CI, or testing the fallback):

```bash
ALEF_SELF_HOSTED_FONT=1 make build     # force self-hosted
ALEF_SELF_HOSTED_FONT=0 make build     # force Google Fonts
```

**Do not edit `SELF_HOSTED_FONT` on the server.** A local edit there is what makes
`git pull` abort with "local changes would be overwritten by merge".
